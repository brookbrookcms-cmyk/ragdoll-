# Asset pipeline and rendering limits

The current anatomy starts from the named Écorché structures credited in
`ANATOMY_ATTRIBUTION.md`. `generate_v10_anatomy.py` imports the source GLB in
Blender, decimates each structure for mobile, fits it to each R15 body region,
and exports FileMesh v2 files. `v15-bone-index.json` preserves the named bone
boundaries. `generate_v15_clean_skins.py` converts the game's available R15
meshes into clean FileMesh assets; the game's private head asset requires a
rounded substitute generated by `generate_v17_head.py`. The script clips
these meshes at hit positions and welds the results to the matching body part.
V24 keeps the game head for small local hits and exposes only nearby skull
and facial muscle geometry. At least three head hits are required before the
cuttable head shell replaces the original and reveals a fitted skull, facial
muscle, and brain assembly at the wounds. `generate_v21_brain.py` makes the
brain approximation. `generate_v24_skin.py` creates the cuttable head shell
and a seamless skin color texture, also used for bare arm surfaces when no
clothing or mesh texture is present. It has subtle color and pore variation,
but the original game's face cannot be transferred to it because that head
asset is private and its UV map is unavailable.
The script also derives one deep internal backing surface from the actual
body mesh for each body wound.
`generate_v18_organs.py` fits the existing heart and lung meshes inside
the upper torso. Those organ meshes are a layering aid; a professional sculpt
and texture pass would still be required for close-up realism. The runtime
tissue backing closes visual gaps; it does not constitute a medical volume
model of all human tissues.

For a higher fidelity asset set, sculpt skin, fat, muscle, bone, and damaged
surface variants in Blender. Retopologize for mobile, preserve matching bind
poses, unwrap UVs, bake color/normal/roughness maps from the high resolution
sculpt, and check silhouette and seams at game scale. Export separate LODs and
test each R15 pose, clothing combination, and ragdoll rotation before release.
Wound edges should be authored as part of the damaged skin mesh, with tissue
layers fitted beneath them. Avoid a reusable red ring or planar cap.

Roblox `SurfaceAppearance` normal and roughness maps require suitable
`MeshPart` assets uploaded through Roblox's asset pipeline. The runtime
FileMesh plus `SpecialMesh` route used by this client script supports a color
texture but does not provide that PBR stack. A client script cannot extract
the game's private head mesh or reliably replace server-owned ragdoll physics.
Uploaded, accessible replacement assets and supported runtime loading would
be necessary to reach the requested sculpted/PBR look. These scripts change only local
visuals and keeps the game's hit and damage systems authoritative.

V24 varies local cut depth, spread, and size using weapon attributes or an
equipped Tool name when the game exposes one. These are visual profiles, not
ballistic simulation: the client does not receive reliable projectile mass,
velocity, trajectory, penetration, or server impulse data for every hit.
Body wounds progress through three exposure stages. The tissue backing sits
behind the opening at each stage. HIGH quality adds a brief fine mist and a
small delayed drip after the directional spray; these are particle effects,
not fluid simulation.
